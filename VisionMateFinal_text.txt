ABSTRACT
Visual impairment presents significant daily challenges, often requiring
individuals to use multiple assistive tools for reading, navigation, and digital
information access. To address this, we introduceVisionMate, a voice-guided
Android application that integrates AI-powered assistive technologies into a
single platform for blind and visually impaired users.
VisionMate is built around two core modules. ABraille Recognition
and Digitizationpipeline uses image preprocessing, page detection, and
a custom-trained Convolutional Neural Network (CNN) to segment and
recognize Braille cells, converting physical Braille into structured digital text.
ASmart Digital Librarywith Semantic Voice Search employs a lightweight
MiniLM sentence-embedding model to generate vector embeddings, enabling
users to retrieve documents through contextual voice queries using cosine
similarity instead of file names.
The application also providesOCR-based document readingwith
contextual web assistance and aYOLO-based Scene Description and Indoor
Navigationmodule for environmental awareness, obstacle detection, and
navigation guidance. For user safety, agesture-triggered Emergency SOS
feature detects predefined phone shake patterns and automatically sends
SMS alerts with GPS coordinates to emergency contacts.
VisionMate follows an offline-first architecture using optimized
TensorFlow Lite models for fast, privacy-preserving on-device processing
with minimal internet dependency. A fully voice-driven interface based on
Automatic Speech Recognition (ASR) and Text-to-Speech (TTS), together
with a lightweight device-based identity system, enables seamless interaction
without visual input , promoting greater accessibility, independence.

CHAPTER 1
INTRODUCTION
Visual impairment affects hundreds of millions of people worldwide, and
for this population, everyday tasks that sighted individuals perform without
conscious thought reading a printed letter, locating a stored document, or
noticing an obstacle on a footpath — become significant sources of daily
difficulty. Assistive technology has traditionally responded to this problem
in fragments: Braille embossers handle reading and writing, dedicated
OCR scanners handle printed-text conversion, GPS units handle outdoor
navigation, and separate mobile apps handle object recognition or emergency
alerting. A visually impaired user is therefore often forced to learn, carry, and
switch between several specialized devices just to accomplish what would
otherwise be a single, continuous task in daily life. The need for one unified,
accessible platform has never been more pressing.
The core challenge lies in this fragmentation and its cost. Each additional
device adds financial burden, a separate learning curve, and a dependency
on being carried at exactly the right moment. This is particularly limiting
in situations that demand a quick response, such as an emergency, where
fumbling between multiple apps or devices can cost precious time. None
of the existing tools, individually or together, offers a low-cost, voice-first
experience that spans reading, organization, mobility, and safety. A number
of existing systems already address parts of this problem, but each covers
only a slice of it. General-purpose screen readers such as Google TalkBack
make Android interfaces navigable by voice but offer no specialized support
for Braille, document search, or scene understanding. AI-driven apps like
Microsoft Seeing AI and dedicated hardware such as OrCam MyEye can read

LITERATURE REVIEW
Assistive technology for visually impaired individuals has historically
developed as a collection of narrow, single-purpose tools rather than a
unified system, and the literature surveyed for this project reflects that same
fragmentation. Seven prior works were examined in detail, spanning Braille
recognition, camera-based navigation, semantic document retrieval, optical
character recognition, and emergency alerting, and each of these strands
maps closely onto one of the technical modules proposed for VisionMate.
Reviewing them cluster by cluster, rather than as an unordered list, makes it
possible to see both how far each sub-domain has progressed on its own and
how little effort has been directed toward combining these capabilities into a
single, offline-capable, voice-driven platform.
Braille accessibility has received sustained attention from the computer
vision community, and two works in this review address it from different
technical angles.Vamshi et al. (2024),[ 1],proposed a Convolutional Neural
Network (CNN)-based approach for recognizing segmented Braille cells and
converting them into machine-readable text.Their work demonstrated that a
custom-trained CNN is a viable classifier for Braille cell recognition, which
directly supports the classification approach adopted in VisionMate’s own
Braille pipeline. However, its scope stops at classification: it does not address
text-to-speech output, multilingual handling, or on-device deployment, and
it is in this sense a strict methodological subset of the recognition problem
rather than a complete assistive solution. The stronger of the two,Dholvan
et al. (2025),[ 2],introduced an end-to-end Braille recognition framework

adopted in VisionMate, as blind users cannot rely on every building they

4.2 Existing System
Currently, assistive support for blind and visually impaired users typically
relies on:
• Screen Readers (e.g., TalkBack):General-purpose accessibility tools
that read on-screen UI elements aloud, but offer no specialized support
for Braille digitization, document search, or scene understanding.
• Dedicated Braille Hardware:Braille embossers and note-takers digitize
Braille effectively but are prohibitively expensive and remain isolated
from any broader reading, search, or navigation workflow.
• Cloud-Based OCR/Object Recognition Apps (e.g., Seeing AI, OrCam):
Capable of reading text or recognizing objects, but dependent on
continuous cloud connectivity, introducing latency, data costs, and
privacy exposure.
• Motion-Based Navigation Aids:Basic obstacle-detection tools that
trigger on any movement, generating frequent false alerts from ordinary
environmental clutter such as swaying curtains or passing shadows.
• Manual Emergency Procedures:Locating a phone, unlocking it, and
manually dialing or messaging a contact during an emergency – a
process that can be slow or impossible for a visually impaired user
under stress.

4.3 Limitations of Existing System
• Fragmentation:No single tool spans reading, document organization,
mobility, and safety – users must learn and carry multiple devices.
• Lack of Semantic Understanding:File-based digital libraries require
users to remember exact file names, offering no way to search by
meaning or context.
• Cloud Dependency:Many existing tools require constant internet
access, making them unreliable in poor network conditions and raising
privacy concerns over transmitted images.
• High False-Alert Rates:Motion-based navigation aids cannot
distinguish a genuine obstacle from harmless environmental
movement.
• Slow Emergency Response:Manual emergency procedures cost
precious time exactly when speed matters most.
• High Cost:Dedicated Braille hardware remains financially out of reach
for many users.
Existing assistive technologies successfully address individual tasks such
as reading, navigation, and emergency support. However, they operate
independently, requiring users to rely on multiple applications or devices.
This fragmentation, together with cloud dependency, high cost, and limited
integration, highlights the need for a unified and accessible assistive platform
such as VisionMate.
